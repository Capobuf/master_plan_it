# Research — Feature 001 Platform foundation

Verification date: 2026-08-04. Primary research is centralized in `docs/replatform/technical-research.md`. The package-specific global-role decision was verified against [Spatie Permission v8 Teams permissions](https://spatie.be/docs/laravel-permission/v8/basic-usage/teams-permissions) and the locked 8.3.0 source.

| ID | Decision | Reason | Rejected |
|---|---|---|---|
| RES-001-001 | PHP 8.3.32 + Laravel 13.22.0 | Current supported floor and framework release; Composer platform prevents accidental PHP 8.4+ dependencies. | floating PHP/Laravel or `--ignore-platform-reqs` |
| RES-001-002 | Sail 1.64.0 canonical environment | Official Laravel Docker workflow, same commands for developers/agents/CI. | custom Docker stack without verified need |
| RES-001-003 | MySQL 8.4.10 only | LTS, minimal compatibility matrix, likely hosting support. | speculative MySQL 9.x matrix |
| RES-001-004 | Filament 5.7.3 + Livewire 4.3.3 | Compatible current releases; native components cover shell/forms/tables. | Preline or second UI kit |
| RES-001-005 | Spatie Permission 8.3.0 teams + Shield 4.3.1 | Laravel 13/Filament 5 compatible; tenant-scoped configurable roles. | custom ACL, fixed role branches |
| RES-001-006 | Typed singleton platform settings | Only one approved global value initially; relational typed validation and concurrency. | generic key/value settings package |
| RES-001-007 | Application-owned audit table | Dynamic retention/minimization/no-export requirements are small and explicit. | generic audit-log package |
| RES-001-008 | Persistent separate test DB without reset traits | Approved project safety contract. | RefreshDatabase/DatabaseTruncation |
| RES-001-009 | Database notifications + sync email | One cron, no worker, visible mail failure. | Redis/WebSockets/queued notifications |
| RES-001-010 | `composer validate --strict --no-check-all` with exact direct pins | Composer 2.7.1 otherwise turns its generic “avoid exact constraints” advice into a non-zero strict result, contradicting the mandatory reproducible pins; schema, lock and every other strict validation remain enabled. | floating constraints; dropping `--strict`; ignoring platform requirements |
| RES-001-011 | Immutable release ZIP after quality gates | Hosting runs verified artifact unchanged. | build dependencies/assets on production host |
| RES-001-012 | Audit retention integer 1–120 months, default 24 | Gives the Administrator a bounded setting while preserving the approved default. | unbounded value or fixed 24 months |
| RES-001-013 | Generic retention-reduction warning without preview | Product selected a warning that discloses neither cutoff nor eligible-event count. | calculated cutoff/count preview |
| RES-001-014 | Ordinary logout uses Laravel 13 `SessionGuard::logoutCurrentDevice()`, then invalidates the current session and regenerates its CSRF token; the Filament 5 logout controller is replaced through the container binding because its native `logout()` rotates the account-wide remember token | Preserves other database sessions and remember-cookie validity on other devices while fully clearing and rotating the current request session. Password change/reset retain their distinct all-session behavior. | Filament native `logout()` rotating the shared remember token; deleting every database session; preserving the current session ID/CSRF token |
| RES-001-015 | WCAG 2.2 AA and explicit browser/viewport matrix | Provides measurable launch compatibility and accessibility acceptance. | unspecified “responsive/accessibile” claim |
| RES-001-016 | Shared `AuditRecorder` requiring `AuditProperties`, recursively rejecting sensitive/non-JSON-safe values and limiting encoded properties to 16,384 bytes | Makes the existing minimized/bounded write-side contract enforceable once for every Action while retaining event-specific validation in the owning Action; 16 KiB is a conservative technical ceiling for metadata-only audit records, not business payload storage. | raw `AuditEvent` writes in each Action; unbounded JSON; database trigger or generic audit package |
| RES-001-017 | Reserve Spatie team key `0` solely for the tenantless platform-Administrator assignment, give that global role the complete stable catalogue, and isolate access through a context-restoring boundary that reloads the persisted active tenantless User identity by its unchanged original primary key before every assignment, protected-role check and ability check | Spatie Permission 8.3 requires a non-null team key on model-role pivots even for a global role. MySQL tenant IDs begin at 1, so `0` is not a Tenant; the boundary temporarily selects it, clears loaded permission relations, performs the check or assignment, and restores the prior team in `finally`. Requiring an existing model whose current key exactly equals its original persisted key, then reloading that row, prevents stale or force-filled in-memory ID, `tenant_id` or active attributes from impersonating another Administrator, elevating another identity, elevating a persisted tenant user or retaining a deactivated Administrator. The complete catalogue implements the approved Administrator actor scope, while Policies, explicit tenant context and domain invariants still gate every operation. | trusting mutable in-memory User identity or eligibility attributes; reload by a caller-mutated primary key; nullable package pivots contrary to the supported migration; a fake Tenant row; assigning Administrator separately to every tenant; protected-only Administrator unable to operate in selected tenants; `Gate::before` invariant bypass |
| RES-001-018 | Root seeding creates no demo identity; Administrator bootstrap creates only an absent email and otherwise accepts only an already protected Administrator | Prevents a known factory password or any pre-existing tenantless account from being silently elevated. First provisioning is explicit and environment-only; reruns are idempotent without implicit password rotation, while all other email collisions fail before mutation. | demo user; takeover/password replacement of a pre-existing account; elevation with its old credential; silent Administrator password rotation |
| RES-001-019 | Correlation uses lowercase UUID v4 in `X-Correlation-ID`, shared across request attribute, scoped binding, normal/error response and log context; invalid inbound values are replaced, and context is cleaned only after response/error reporting | One validated identifier satisfies diagnostics without creating a new validation error surface. Laravel's exception `context`/`respond` hooks retain the same ID when the pipeline unwinds, while terminal cleanup prevents long-lived-process and consecutive-test leakage. | trusting/echoing arbitrary inbound text; rejecting requests only for diagnostic header syntax; random second ID on errors; early `finally` cleanup; process-global leak |

## Executable gates

- Composer exact resolution on platform PHP 8.3.32;
- package migration inspection before publish;
- Spatie team-context request isolation test;
- Shield permission generation diff reviewed and committed;
- no destructive DB reset static guard;
- production artifact content/manifest test.

A failed gate blocks the feature and requires an ADR amendment. No automatic alternative is selected.

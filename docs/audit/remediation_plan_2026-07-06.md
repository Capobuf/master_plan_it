## Implementation Plan

1. Do not overwrite contract-generated expense rows. Reclassify FINDING-001 based on existing code and tests: append-only is intentional for new terms, but edits to already-synced terms can leave stale generated rows and there is no source snapshot/hash/manual override policy.
2. Preserve Plafond as an `MPIT Expense` kind. Use financial-engine row calculations as the source of truth for Plafond allocation/consumption/remaining, and align the user-facing MPIT Expenses report with those calculated fields instead of treating parent Ordinary totals as Plafond totals.
3. Centralize billing-cycle allocation logic in `annualization.py` so annual amounts not divisible by 12 keep their annual total when the whole year overlaps, while final values remain rounded to 2 decimals.
4. Keep server VAT validation authoritative. Update the expense client script to load MPIT Settings VAT defaults, preview net/VAT/gross with the same priority as the server, and block save client-side when a non-zero row has neither local VAT nor default VAT.
5. Normalize Dashboard Chart Source JS namespace initialization with `frappe.provide("frappe.dashboards.chart_sources")`; do not change chart methods, filters, names, or dataset logic.
6. Clean only generated bytecode artifacts. Do not remove `old_parent`, migration patches, or metadata fields with possible historical data.

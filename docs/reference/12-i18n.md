# Reference: Translations (i18n)

## TL;DR

- Source of truth: `master_plan_it/master_plan_it/locale/main.pot` + `master_plan_it/master_plan_it/locale/it.po`
- Runtime artifact: `master_plan_it/master_plan_it/locale/it/LC_MESSAGES/main.mo` (generated)
- DocType JSON labels auto-extract; code strings still require explicit `_()` / `__()`

## Marking Strings

| Context | Syntax | Example |
|---------|--------|---------|
| Python | `_(...)` | `_("Welcome {0}").format(name)` |
| JS | `__(...)` | `__("Welcome {0}", [name])` |
| Jinja | `{{ _(...) }}` | `{{ _("Total") }}` |

## Literal String Rules

- Use literal strings only (no variables)
- Positional placeholders: `{0}`, `{1}`
- No concatenation, multiline, trailing spaces
- Context for ambiguous terms: `_("Change", context="Switch")`

## Native PO Workflow (Frappe v16)

```bash
bench generate-pot-file --app master_plan_it
bench update-po-files --app master_plan_it --locale it
bench compile-po-to-mo --app master_plan_it --locale it --force
```

One-time migration from legacy CSV:

```bash
bench migrate-csv-to-po --app master_plan_it --locale it
```

## PO Entry Example

```po
msgid "Welcome {0}"
msgstr "Benvenuto {0}"
```

## What NOT to Translate

- DocType names, fieldnames, module names
- Route paths, DB keys
- App/product names (unless in glossary)

## Verification

1. Set user language to Italian
2. Confirm `locale/main.pot` and `locale/it.po` exist
3. Run `bench compile-po-to-mo --app master_plan_it --locale it --force`
4. Hard-refresh browser
5. If stale: `bench --site <site> clear-cache`
6. If still stale: restart bench services

## Common Issues

| Symptom | Cause |
|---------|-------|
| String not translated | Not wrapped in `_()` / `__()` |
| Still stale after update | `.po` changed but `.mo` not compiled |
| Wrong file location | Files must be under `master_plan_it/master_plan_it/locale/` |

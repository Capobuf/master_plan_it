## Non-overlapping task contract

A task is Ready only when all four records agree:

1. `specs/<feature>/tasks.md` owns the stable ID, class, objective, exact dependency IDs, requirement IDs, implementation sequence, tests-first order, expected result and forbidden work;
2. this registry owns only source links, inherited invariant IDs and stable error codes;
3. `docs/replatform/task-execution/feature-<NNN>.md` owns the exact validation command for the task ID;
4. `docs/replatform/task-execution/path-overrides.md` owns only complete repository-relative path expansions where the task entry uses an abbreviated path list.

No record may override a field owned by another record. In particular, this registry contains no dependency overrides and no path overrides. A disagreement is a documentation blocker; the implementation agent must stop rather than infer a precedence rule.

## Stable task classes

- `[FND]`: setup or shared technical foundation. It may create required infrastructure but no user-story-specific behavior.
- `[USn]`: implementation or test work owned by the numbered user story in the feature spec.
- `[VER]`: verification, evidence or documentation only. It may not create runtime behavior, production workflows, commands, pages, Actions or services.

## Readiness gate

A task is not Ready when:

- its dependency field contains prose, a range, a wildcard or an unnamed prerequisite;
- a required path remains abbreviated without one exact row in `task-execution/path-overrides.md`;
- its task ID is absent from the owning feature command register;
- a `[VER]` task creates runtime behavior;
- requirement, invariant or error ownership is missing;
- any record contradicts another.

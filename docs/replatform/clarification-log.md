# Product Clarification Log

| Question ID | Decision | Date | Affected artifacts | Consequences |
| ----------- | -------- | ---- | ------------------ | ------------ |
| Q-001 | Replace the four legacy product roles with three roles. `System Manager` and `vCIO Manager` converge into global `Administrator`; `Client Editor` is renamed `Editor`; `Client Viewer` is renamed `Viewer`. | 2026-08-02 | Constitution; all feature specs; every authorization contract; migration mapping; quickstarts; tests; traceability. | All role matrices and legacy-user mappings must converge on three roles. Administrator retains global scope and does not bypass domain invariants. |
| Q-002 | Tenant lifecycle is `Active`/`Inactive`. Only Administrator may create, deactivate, and reactivate tenants. Permanent tenant deletion is not available. Data, users, attachments, and audit are retained while inactive. | 2026-08-02 | Tenancy feature; data model; tenant-context contract; operations; audit; authorization; risk register. | Deactivation blocks tenant-bound use without destroying history and must be reversible by Administrator. |
| Q-003 | Only Administrator creates, invites, updates, and deactivates Editor and Viewer accounts. A tenant may have multiple Editors and multiple Viewers. | 2026-08-02 | Tenancy spec; user-management screens; authorization matrix; onboarding; migration; tests. | Tenant users cannot administer other users. User membership remains single-tenant for Editor and Viewer. |
| Q-004 | Administrator selects an explicit tenant context and continues to act under the Administrator identity. Impersonation is not part of the product. Every action remains attributed to the Administrator. | 2026-08-02 | Tenant-context contract; audit; screen shell; session behavior; authorization; acceptance tests. | The UI must expose active tenant context and audit must distinguish Administrator actions from tenant-user actions. |
| Q-005 | Viewer receives complete read access to the tenant’s operational data, economic amounts, detail rows, projects, contracts, vendors, cost centers, plafond, attachments, audit, reports, print, and export. Viewer cannot write, administer tenant users, or perform global operations. | 2026-08-02 | All feature authorization contracts; navigation; reporting; export/print; attachments; audit; tests. | Viewer is a comprehensive tenant read-only role, not a dashboard-only role. |
| Q-006 | Editor may create and modify expenses, add Estimate, Quote, and Actual rows, replace non-Actual rows, and manage plafond. Recorded Actual and economic history remain immutable. | 2026-08-03 | Feature 003 spec, authorization, editor contract, data model, tasks, tests. | Editor supports ordinary economic work without receiving a history-rewrite path. |
| Q-007 | Editor manages vendors and cost centers. Only Administrator configures financial years. | 2026-08-03 | Feature 002 spec, screens, authorization, data model, tasks. | Master-data permissions are explicit and tenant-scoped. |
| Q-008 | Editor manages projects, contracts, stages, terms, and renewals. Generated identities and already-used history remain system-controlled. | 2026-08-03 | Feature 004 spec, contracts, generation sync, tasks, tests. | Editor controls business workflow without directly changing generated source identity. |
| Q-009 | Editor may export, print, create scenarios, manage attachments, and read tenant audit. Import, migration, backup, restore, and user management are Administrator-only. | 2026-08-03 | Features 001, 003, 005, 006, 007; authorization and operation contracts. | Operational utilities and global administrative operations are separated. |
| Q-010 | All business data is tenant-owned. Global data is limited to tenant registry, accounts, roles, technical configuration, and system currency/language/timezone lists. | 2026-08-03 | Constitution, all feature data models, report/query contracts, migration. | Cross-tenant business catalogues and shared mutable business data are excluded. |
| Q-011 | Each Frappe site represents one customer. The one active site is migrated manually or through CSV into an explicitly selected tenant. | 2026-08-03 | Feature 006 spec, migration/reconciliation contracts, tasks, roadmap. | No generalized multi-site migration platform is required. |
| Q-012 | Tenant creation requires display name, unique code, currency, language, timezone, and default VAT rate. Logo, company data, address, and contacts are optional. | 2026-08-03 | Feature 007 spec, data model, validation and onboarding contracts. | A new tenant is operational without forcing nonessential company fields. |
| Q-013 | Tenant may configure name, logo, company data, currency, language, timezone, default VAT, and report header/footer. The application shell retains Master Plan IT branding. | 2026-08-03 | Platform shell, tenant settings, reporting contracts, data model. | Reports are tenant-branded; the application is not white-label. |
| Q-014 | Administrator global overview includes tenant list/state, Editor and Viewer counts, last activity, tenant entry, operational alerts, renewals, and import/migration errors. No cross-tenant economic aggregation is included. | 2026-08-03 | Feature 005 and 007 specs, dashboard contract, traceability and tests. | Global view is operational rather than an economic comparison dashboard. |
| Q-015 | Current tenant is always visible in side navigation and page breadcrumbs. Only Administrator can change tenant context. | 2026-08-03 | Platform shell, tenant-context contract, UX checklist and browser tests. | Wrong-context risk is reduced without subdomains or impersonation. |
| Q-032 | Closed as a duplicate of Q-013. Tenant name, logo, company data, and report header/footer are configurable for tenant-facing output; application-shell branding remains Master Plan IT and optional branding fields remain optional. | 2026-08-03 | Tenant settings; reporting contracts; product clarification register. | No additional product choice is introduced; the prior Q-013 decision resolves this lower-priority duplicate. |
